## Three things the pilot revealed

**1. Type B reduction is real on 2/3 tasks — including the anchor.** network-tools (−56%) and Permuted (−43%) both drop clearly; Data Siege is flat. And it's the right dissociation: Type B falls while Type A doesn't (A even rises), so it's mechanism-specific, not a global effect.

**2. Promotion and Type-B reduction are decoupled — a genuinely important finding.** Look at the pairing:

- network-tools: **big B drop, but promotion did NOT fire.**
- Data Siege: **promotion fired, but B flat.**

So dead-end promotion is neither necessary nor sufficient for the improvement. The reduction is coming from FAEM's _recent-failed-attempts_ injection (the "you already tried X" block), not the technique-class promotion specifically. That reframes what's doing the work.

**3. The gateway suppresses promotion on exactly the attack tasks.** network-tools promotion didn't fire because its command-injection reflections hit the content policy → `unclassified` → no promotion (Data Siege/Permuted are benign enough to classify, so they fired). This is the **methodological blocker for the full batch**: on Haiku/gateway, your anchor task can never demonstrate Dr. Chen's criterion #1 (dead-end detection), for an infrastructure reason, not a task reason.

Therefore, GPT takes over if content safeguards block anything on claude.

1. **Detecting a dead end (promotion):** fires on 2/3 — but **not on the anchor** (network-tools). And now we _know why_, cleanly: the gateway fix removed the 403 confound, so reflections classify `command_injection` correctly — yet the agent **interleaves** classes (`ci, ci, info_disc, ci`), max consecutive run = 2, and promotion needs 3 _consecutive_. This is a **real mechanism finding**: the `DEAD_END_THRESHOLD=3-consecutive` trigger rarely matches an interleaving agent.
2. **Reducing cost (fewer wasted repeats):** Type B down on 2/3 (−44%, −43%), flat on 1. Good signal.
3. **Detecting failures earlier (time-to-pivot):** network-tools 1.5→1.0 (FAEM pivots ~33% faster). Only network-tools has nonzero time_to_pivot, so it's the one task that exercises this metric.
4. **Progress in step window:** all capped at 15 (expected on hard tasks; solve-bool is the wrong lens, as established).

**FAEM reduces repeat-failures, but via the _recent-failed-attempts memory_, not dead-end promotion.** The two are decoupled: network-tools' B drops 44% _with no promotion_, while Data Siege promotes but B stays flat. Promotion (criterion #1) is largely inert here because the interleaving agent almost never trips the 3-consecutive trigger.
