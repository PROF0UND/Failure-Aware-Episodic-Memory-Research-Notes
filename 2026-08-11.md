`distinct_subtasks == turns == 15` on every run. The **reasoning module already never picks the same sub-task node twice.** So the loop is _not_ at task-selection — it's at **command generation**: different sub-task nodes emit the same command. But FAEM injects its dead-end/reflection block only into the decide step ([reasoning.py:252](vscode-webview://1avbl4i0e6mfh0ejcukt31vo5242lu9l20trip9on2od7ajfmncb/pentestgpt/reasoning.py#L252)); the `GenerationModule` that actually writes the looping command gets only the subtask string ([orchestrator.py:132](vscode-webview://1avbl4i0e6mfh0ejcukt31vo5242lu9l20trip9on2od7ajfmncb/pentestgpt/orchestrator.py#L132)) and has no memory. **You're applying the anti-repeat signal to the one stage that already doesn't repeat.** Permuted improved only as a second-order side effect (changing the chosen node happened to change the command). That's why the effect is weak and inconsistent rather than decisive.
